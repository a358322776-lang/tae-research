## 0. 为什么先跑模拟盘

冻结稿 v0.1 已定：$1000 纸面口径、56U 真实账户不可执行。
而 v0.3 盈利实测证明：**成本不敏感，延迟致命**——

| 执行延迟 | 样本外年化 |
|---|---|
| T+1 | 12.9% |
| T+2 | **3.5%** |
| T+3 + 高成本 | **-0.2%** |

所以模拟盘只回答一个问题：**你的链路从日线收盘到最后一笔订单，实际要多久？**

## 1. 交付物

| 文件 | 作用 |
|---|---|
| `paper_run.py` | 运行器（单文件，无依赖除 pandas/ccxt） |
| `state_paper.json` | 持仓 + 纸面权益（自动生成） |
| `paper_ledger.csv` | 逐笔台账（追加写，不改写历史） |
| `timing_log.csv` | **每次运行的耗时记录（核心数据）** |

## 2. 实测结果（2026-10-31 首跑）

```

[2026-10-31] fetched 60/60 symbols in 60.3s
  held 0, planned exposure 0.0%, paper equity 1000.00
  END-TO-END LATENCY: 0.02 h
```

- **60/60 币全部成功**，0 错误
- **抓取耗时 60.3 秒**（12 线程并发；单线程版本是 180 秒，已优化 3 倍）
- 当日 0 个突破信号（市场宽度低，与 v0.2 §3 一致）
- 端到端延迟 **0.02 小时 = 1.2 分钟**

**这 60 秒是纯数据抓取，还不含下单。** 有信号的那天，要在此基础上加 60 笔订单的执行时间。

## 3. 使用方法

```bash
# 每天 UTC 00:05 之后跑一次（日线已收盘）
export HTTP_PROXY_ALL=http://127.0.0.1:7890     # 国内必需
python paper_run.py --run

# 查看累计统计（延迟中位数、p90、纸面盈亏、信号数）
python paper_run.py --report

# 离线模式（用本地 CSV，不连交易所）
python paper_run.py --run --offline
```

**关键设计：**

- **幂等**：同一天重复跑会打印 `!! duplicate run`，不会重复记账
- **只用已收盘 K 线**：当日未完成的那根永远被丢弃
- **状态持久化**：`state_paper.json` 记录持仓和权益，中断不丢
- **只用 `shift(1)`**：与 `core.py` 完全一致，无未来函数

## 4. Muse 接手的六个问题（必须逐条回答）

冻结前请 Muse 确认：

1. **调度**：谁在 UTC 00:05 触发？cron 还是手动？如果手动，人能保证每天准点吗？
2. **代理**：服务器上代理是否稳定（币安 API 国内直连超时，实测必须走代理）？
3. **失败重试**：60 个币里若有几个抓不到（实测 0，但网络抖动会），是否重试？重试几次？
4. **信号与下单的边界**：本运行器只出信号。**真实下单的执行器在哪？** 若不存在，模拟盘的延迟数据不含下单环节，会低估总延迟。
5. **记录位置**：`timing_log.csv` 是否每天入库（不是 git，是本地持久化）？
6. **判读门槛**：延迟中位数 ≤ 2 小时才算通过，2-12 小时要重新考虑，> 24 小时直接放弃。

## 5. 判读规则（写死，来自 v0.3 实测）

| 延迟中位数 | 结论 |
|---|---|
| ≤ 2 小时 | 进入前向验证 |
| 2 - 12 小时 | 预期年化跌到 3-8%，重新考虑是否值得做 |
| > 24 小时 | 终止，该策略在你的链路上不可执行 |

**建议至少跑 21 个交易日**（约 1 个月）再判读，覆盖周末和网络波动。

## 6. 本运行器不做什么

- ❌ 不下单、不碰真钱、不读 API key
- ❌ 不修改 `core.py` 或任何冻结规则
- ❌ 不替代前向验证（冻结后仍需按 F-TR3-1~8 独立判读）
- ❌ 不含滑点实测（只在纸面按收盘价记账；真实滑点需另测）

## 7. 已知限制

1. 纸面按收盘价成交，真实滑点未建模
2. 延迟只测到"信号算完"这一刻，若下单环节另有耗时，需加进 `timing_log.csv`
3. 60 秒抓取是本地+代理环境下的实测值，服务器环境可能不同，需在目标机器上重测
4. 当日 0 信号不代表常态；有信号日的延迟会更高
