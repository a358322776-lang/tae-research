## 0. 目标与非目标

- 目标：把 `paper_run.py` 的信号变成可计量的真实成交链路（测试网先行），测出**含下单**的端到端延迟与真实滑点，补上纸面运行器“不含下单”的缺口。
- 非目标：不改策略规则（20/10、60 币、T+1 收盘执行、1/60 仓位），不做资金管理，不碰已有期货 live 执行器与密钥。

## 2. 密钥与安全（硬规则）

- 新开专用 key：**只勾现货交易**，提现权限关闭，IP 白名单只认部署机；测试网 key 与主网 key 分离，各用各的。
- 密钥只放运行机环境变量，**永不进仓、永不进聊天、永不进日志**；密钥由用户本人在币安 API 管理页创建并核对权限清单（人工核对项，不声称有接口自检）。
- 三重门：显式 `--live` 标志 + 本地配置文件 `enabled: true`（本地 only）+ 无 `STOP` 文件，三者缺一即只跑纸面。
- 每日上限：订单数 ≤ 60、日名义 ≤ 当日权益；单日失败订单 > 5（默认阈值，待定）即停新单并记日志。
- 熔断：`STOP` 文件存在、交易所返回 418、余额不足，任一即停单（不自动减仓、不自动重试下单）。

## 3. 架构

- 单进程 cron 任务，复用 `paper_run.py` 的信号部分（60 符号宇宙、`shift(1)` 水平、状态机），新增下单与对账模块；状态文件复用 `state_paper.json`，订单台账另存本地（永不进仓）。
- 客户端默认 ccxt（与现有代码一致，负责签名与时间戳）；模块划分：fetch → signal → size → place → reconcile → log。

## 4. 订单流程

- **触发**：cron 在 UTC 00:05 后运行；丢弃未完成当日 K 线，只用已收盘数据。
- **信号**：与 `core.py` 一致（20/10 收盘突破/跌破，状态机持有至出场信号）。
- **订单类型（默认待批）**：市价单 MARKET。理由：回测假设“收盘价成交”，市价单最接近该假设；限价单可能不成交、滑向 T+2，而 v0.3 已证 T+2 致命。
- **数量**：
  - 买入用 `quoteOrderQty`（USDT 金额 = 1/60 权益）：官方语义为市价单用 `quoteOrderQty` 不破 `LOT_SIZE`，按名义值就近成交。
  - 卖出用 `quantity`，向下取整到 `MARKET_LOT_SIZE` 的 stepSize；余零头留作 dust，不追。
  - 下单前读 `exchangeInfo` 校验 `PRICE_FILTER` / `LOT_SIZE` / `MARKET_LOT_SIZE` / `NOTIONAL`（minNotional 按币种实测值，不预设统一值）；低于 minNotional 的腿跳过并记为执行缺口，不补单。
- **幂等**：`newClientOrderId` 确定性生成（`TR3_<日期>_<符号>_<方向>`）。官方语义：同 ID 订单在前一单未成交前会被拒；超时或歧义响应时，先 `GET /api/v3/order` 用 `origClientOrderId` 对账，再决定是否重发，绝不盲重发。
- **重试**：仅可重试错误（超时、5xx、429 按 Retry-After 退避）最多 3 次；不可重试错误（-1013 filter、-2010 余额不足、-1021 时间戳）直接记失败；429 频发会招 418 封 IP，退避优先于速度。
- **部分成交**：剩余不追单，记执行缺口；不改信号、不补仓。
- **频率**：顺序或 ≤5 并发；60 单/日远低于 10 单/秒与 10 万单/日上限，权重预算内。
- **对账**：下单后查订单状态与账户余额；逐单记意图价（收盘）、成交均价、滑点、手续费、缺口；日终对账报告只存本地。

## 5. 阶段门

- S0 纸面（已有 `paper_run.py`）：只记账，不下单。
- S1 测试网（`testnet.binance.vision`，独立 key，假资金）：≥ 21 个交易日（默认，待定），测含下单延迟与滑点；通过标准待定（默认提议：延迟中位 ≤ 2h 且滑点中位在 5bp 假设内——仅提议，须用户定）。
- S2 主网：**仅当前向验证 365 天通过 + 用户另行批准**；首笔主网资金只认 $1000 口径；56U 账户永久排除（低于最小名义，物理上不可执行）。
- 测试网流动性 ≠ 主网：S1 的滑点读数仅供参考，不作主网保证。

## 6. 与冻结稿的关系

- 延迟判读门（中位 ≤ 2h）是 Hermes 的提议，当前冻结稿 v0.1 无此门；如采用，须以修正案写入冻结稿并经用户批准，**在本稿中不擅自设为杀线**。
- 执行器的缺陷修复要求同样适用：重复运行判重必须在改动前（`paper_run.py` 的事后判重缺陷不得带入）。

## 7. 失败模式

| 场景 | 处理 |
|---|---|
| 抓数失败币 > 5 个 | 整轮停单（残缺组合破坏等权假设） |
| 交易所宕机/418 | 不下单，记日志，等下一日 |
| 时间戳偏差 -1021 | 重同步时钟后最多重试一次 |
| 余额不足 -2010 | 停单记日志，不自动减仓 |
| 重复运行 | 改动前判重，直接退出 |
