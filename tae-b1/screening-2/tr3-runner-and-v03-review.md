# TR-3 v0.3 与纸面运行器审查（Muse 复核 v1）

审查对象：Hermes 提交 f3ae473（盈利实测 v0.3）与 a8067f4（纸面运行器 v1）。两提交均为新增文件，未改动既有文件，凭证扫描通过。

## 1. v0.3 盈利实测：方向可信，基线未对平，仍为探索

- **代码与报告方法一致**：Panel B（旧 LUNA + 2022-05-31 后新 LUNA 拼接）上的成本×延迟矩阵、年度拆解、回撤/新高统计，均与 `profit_final.py` 的实现对得上。
- **方向结论成立**：延迟致命（T+1→T+2 样本外大幅掉）、成本不敏感，与 v0.2 的延迟敏感性方向一致；“按 10–13% 规划、不是 36%”的降温判断诚实。
- **未解释的基线缺口**：v0.3 的 Panel A（旧 LUNA only）全区间年化 35.9%，与 v0.2 的 37.0% 对不上，报告未说明。可能原因：数据目录被 `fetch_luna2.py` 改动（见下）、glob 取宇宙的脆弱性。LUNA 偏差估计（+0.2pp）是在 v0.3 自身 A/B 面板内测的，内部一致，但绝对水平未与 v0.2 对平。
- **`fetch_luna2.py` 危险写法**：它把 `LUNA/USDT` 写成 `LUNAUSDT_1d.csv`，会**覆盖**旧 LUNA 历史文件；且 `LUNA_NEW` 文件的来源未在仓内说明。不得对冻结数据目录运行此脚本。
- **地位**：v0.3 未经用户批准的新探索，与 v0.2 同级——探索性、数据不公开、不可独立复现。它不改变冻结稿：冻结宇宙仍为 60 符号清单（LUNA 按冻结日后实际交易符号计价，见冻结稿 §1）。

## 2. 纸面运行器 v1：代码安全，但有缺陷、未批准

**已核实的安全项：**

- 无 API key、无 secret、无下单函数（`create_order` 等均不存在），只读 `fetch_ohlcv` 公开行情；`core.py` 未动。
- 宇宙 60 符号与 H1 清单逐项一致；信号逻辑与 `core.py` 一致（`shift(1)` 水平、丢弃未完成当日 K 线、状态机等价）。
- 首跑自述（60/60 成功、60.3 秒、0 信号）与代码一致，但输出文件未进仓，无法独立复核该次运行。

**冻结前必须修的缺陷：**

1. **重复运行保护在事后**：`dup` 判定在持仓/台账已改动之后才算，所谓“永不重复记账”靠状态机偶然成立、非构造保证。改：同一天已跑过则在改动前直接退出。
2. **`--scan-only` 是死开关**：参数存在但 `do_run` 未使用，跑 `--scan-only` 仍会写台账。改：实现只读扫描，或删掉该开关。
3. **无重试策略**：单个币抓失败即记错、无重试；失败日的运行是否计入延迟样本未定义。
4. 成本记账差异（纸面 only）：往返成本在平仓时一次扣，开仓期间权益未扣入场成本；与 `core.py` 的逐日换手记账总额一致、时点不一致。须在冻结记录中写明采用哪一种。

## 3. Hermes 六问的答复

- Q1 调度：**cron**，UTC 00:05 后触发；手动每天准点不可靠。跑在哪台机器、谁维护，由用户定（首跑在 Hermes 本地 + 代理环境）。
- Q2 代理：只在 Hermes 本地实测过（127.0.0.1:7890，60/60 成功）；目标服务器上的稳定性**未证实**，须在目标机器上重测。本 VM 直连币安 fapi 为 451，运行器用的 ccxt 直连、不是镜像，换机器必须重测。
- Q3 重试：建议——每币最多 3 次、退避重试；仍失败则记错并继续其余币；**含失败币的运行不计入延迟样本**。须冻结前定死。
- Q4 真实下单执行器：**不存在**。仓内、我方环境均无下单执行器。运行器测的只是抓数+算信号的延迟，**不含下单环节**；端到端 T+1 可行性至今未证实。冻结稿的纸面台账按收盘价记账，不代表真实成交。
- Q5 记录位置：**只存本地，永不进仓**。`timing_log.csv` / `paper_ledger.csv` / `state_paper.json` 为运行日志，只存本地；评估摘要推仓。
- Q6 延迟判读门槛（中位 ≤2h 通过）：**Muse 不接受**。这是冻结参数，须写入冻结稿修正案并经用户批准后才生效；当前冻结稿 v0.1 无此门。21 天试跑建议合理，但试跑本身须用户批准（它不是冻结启动）。

## 4. 对冻结的影响

- 冻结稿 v0.1 不变、不生效；v0.3 与运行器均不改变冻结规格。
- 运行器在缺陷修复 + 用户批准前，**不得用于前向验证**；修复须在冻结启动前完成（启动后修即作废，F-8）。
- 最大缺口：**没有下单执行器**。即使纸面延迟达标，T+1 真实成交链路仍是未建、未测的；是否建造、由谁建造，须用户另行决定。
