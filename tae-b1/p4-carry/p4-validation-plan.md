# P4 加密资金费 carry — 独立验证方案

> **状态：方案，未执行。** 本文件只写验证方法，不产生任何验证结果。
> 探索／独立样本外／前向纸面三阶段严格分开；已用数据不得冒充独立样本外。
> 冻结、前向验证、模拟盘均须用户逐个批准；本方案本身不构成批准。

## 0. P1–P4 分离声明（大字，先于一切方法）

**P4 与 P1 分别建档、分别登记、分别验证、分别裁决。**

- P4 的数据（币安资金费＋加密价格）与 P1 的数据（ETF 日线、跨资产动量宇宙）
  是两个互不重叠的数据池（除 BTC/ETH 价格历史在概念上同源外，
  两方向的检验统计量、样本窗口、verdict 完全独立计算）。
- P4 的样本外验证结果不得引用 P1 的结果，P1 的结果不得引用 P4 的结果；
  两方向的样本不得合并、不得互相作为“独立”证据、不得交叉引用显著性。
- 若任一方向的验证引用了另一方向的数据或结果，该验证作废，需重做。
- P4 的前向记录模块与 B1 的前向观察系统无关（后者只记 B1 结构事件，
  一律不动）；P4 的前向记录模块在用户批准方向后另行实施，本方案只描述、不建造。

## 1. 三阶段划分（定义）

| 阶段 | 数据 | 规则状态 | 产出 | 标签 |
|---|---|---|---|---|
| Stage 0：登记（已完成，本次） | 历史市场统计（资金费、基差描述性统计） | 草案，未冻结 | 成本模型、保证金算术、杀线定义 | **不是策略结果** |
| Stage 1：探索性回测（待批准） | 冻结前全部历史（资金费 2020→冻结日、价格 2019→冻结日） | 冻结规则（用户批准草案后冻结） | 统一报告模板全项（§5） | **探索性，绝不冒充独立样本外** |
| Stage 2：独立样本外（待批准） | **仅冻结后前向数据**（见 §2：P4 无 holdout 选项） | 冻结规则，一字不改 | 同模板全项＋杀线裁决 | **独立样本外** |
| Stage 3：前向纸面 → 模拟盘门（待批准） | 冻结后前向纸面记录（与 Stage 2 同一前向流，见 §3 的阶段关系说明） | 冻结规则，一字不改 | 纸面 verdict → 模拟盘门 | **证明可执行正期望的前置门** |

**阶段关系说明（P4 的特殊性）：**
P4 的全部历史（资金费＋价格）均已研究使用，无法切出“设计前零触碰”
的历史 holdout（地图已定：不存在 holdout 选项）。因此 P4 的 Stage 2
**只能是冻结后前向数据**——前向流同时承担“独立样本外”与“前向纸面”
两个角色，但两者是同一前向流上的两次裁决，不是两份数据：
- Stage 2 裁决点：前向数据达到最低样本量（§4）时，用杀线与模板做第一次 verdict；
- Stage 3 裁决点：同一前向流继续积累并通过模拟盘门（用户另行批准）后，
  才谈“证明可执行正期望”标签（§5 七项）。
不得把 Stage 1 的探索数据重新包装成 Stage 2；不得把 Stage 2 的前向数据
在事后挑一段好的子集冒充“独立”——前向流全程计入，子集只作稳定性分解，
不作 verdict 替换。

## 2. 独立样本外的唯一合法来源

- **冻结后新打印的资金费**（实际时间戳）与**冻结后新 bar**。
- 探索触碰过的任何历史子集（包括“冻结日前一天”的数据）一律不算独立样本外。
- 跨资产借用不算独立：BTC 数据不能为 ETH 规格作独立样本外（不同资产、
  不同资金费体制，且 BTC 历史同样已用）；XAU/QQQ 数据与主规格无关，
  不得借用。
- 冻结时点以用户批准冻结的 UTC 时间戳为准，冻结前 1 秒的数据都不算前向。

## 3. 前向纸面记录（描述，待批准后实施，本阶段不建造）

前向记录模块（新模块，B1 观察系统不动）须记录：

| 记录项 | 粒度 | 用途 |
|---|---|---|
| 每次资金费打印（时间戳、费率、对子状态：持有／空仓） | 每次打印 | 资金费收入计量（实际时间戳，不得假设网格） |
| 每日收盘基差（永续收盘 − 现货收盘，UTC 日） | 每日 | Δ美元基差计量、基差风险监控（K5） |
| 对子事件（建仓／平仓／补保证金／强平／ADL，含双腿成交价、手续费、滑点档） | 每次事件 | 净 carry 计量、成本计量 |
| 月末快照（滚动 90 天净 carry、近 365 天均值资金费、p95 \|日基差变动\|、中性相关系数） | 每月末 | 杀线评估（K1/K4/K5/K7） |
| 异常日志（缺口、停机、费率规则变更、USDT 偏离、ADL） | 每次发生 | 暂停／重登记触发 |

**记录纪律：** 只记录、不干预（纸面阶段不产生真实订单）；记录缺失
（缺口）须记入 manifest，不得静默插值；缺口期间的资金费按实际打印补记，
缺失打印记为数据缺口、不得假设为零。

## 4. 样本量与评估协议（冻结时定死，此处为方案值，待用户审查）

**最低样本量（通过 verdict 的必要条件，缺一即不得判通过）：**

| 维度 | 最低要求 | 理由 |
|---|---|---|
| 前向日历 | ≥ 180 天 | 覆盖至少两个季度资金费体制变化 |
| 资金费打印 | ≥ 540 次（约 180 天 × 3 次／天） | 打印数是名义样本，见下行 |
| 资金费体制月 | ≥ 6 个 distinct 月 | **经济样本是体制月，不是打印数**——打印高度自相关（体制驱动），540 次打印 ≠ 540 独立样本；verdict 以月为经济单位 |
| 对子持有 | ≥ 1 个完整持有周期（含至少一次建仓与平仓） | 无完整周期则净 carry 无法闭合计量 |

**评估协议：**

- 月末评估：每月末计算滚动 90 天净 carry（K1）、近 365 天均值资金费（K4）、
  滚动 90 天 p95 \|日基差变动\| ÷ 日均资金费（K5）、窗口内中性相关系数（K7）；
  杀线触发即杀（见 §6），不等待“恢复”。
- **杀线与通过 verdict 的不对称性（纪律）：** 杀线可在样本量未满时提前触发
  （杀 verdict 不需要等满 180 天）；通过 verdict 必须等满最低样本量
  且全部杀线沉默且报告模板齐全——不得以“早期向好”提前判通过。
- 通过 verdict 的评估点：前向满 180 天后的第一个月末；之后每满 90 天
  复评一次（滚动复评不改变历史 verdict，只追加）。
- 探索阶段（Stage 1）的杀线演练：Stage 1 同样计算 K1–K8（验证指标可算），
  探索触发杀线 → 不进前向；探索未触发 ≠ 通过——探索通过只是“允许进前向”，
  不是任何正期望证明。

## 5. 统一报告模板（验证各阶段同款，地图 §5 适配 P4）

| 字段 | P4 口径 |
|---|---|
| 净收益 | 净 carry = 资金费收入 − Δ美元基差 − 手续费 − 滑点；报告单位名义口径（%/名义）与绝对 U 口径（对子名义 20U）双列；中央口径（taker＋0.05% 滑点档）＋敏感性档位 |
| 最大回撤 | 组合净值（USDT 计，含未实现基差浮动）峰值回落；与现金基准（0）与 ETH 买入持有同期回撤并列 |
| 风险调整收益 | 夏普 = 年化净 carry ÷ 年化净 carry 波动（无风险基准 USDT 现金 0%）；索提诺（下行波动口径）附列 |
| 样本量 | 前向天数／打印数／体制月数／完整持有周期数；每子样本（体制段）笔数 |
| 跨时期稳定性 | 按资金费体制分段（高溢价／低溢价／近零年）、按市场方向分段（牛／熊／震荡），任一段净 carry 为负即在报告首页标明 |
| 交易成本敏感性 | 滑点三档（0／0.05%／0.1%）、费率 ×2、资金费开关（计入／不计入）三项，任一档翻负即标明 |
| 相对基准表现 | 相对 USDT 现金（主基准）的超额与回撤对比；相对 ETH 买入持有（参照）的中性相关系数与回撤对照 |
| 资金占用与最小单位核对 | 对子名义、保证金、最小名义、双腿资金占用，逐项核对 56U 现实（§6 数字复核） |
| **二元标签** | **历史正收益** 或 **证明可执行正期望**，二者不得混用（定义见 §6） |

## 6. 二元标签与杀线裁决（地图 §5 定义，P4 适配）

**历史正收益**：仅表示探索样本上扣成本净 carry 为正。仅此而已，
不代表可执行、不代表未来有效。

**证明可执行正期望**：须同时满足以下全部，缺一即不得贴此标签：

1. 规则冻结在先（用户批准冻结，时间戳在前向数据之前）；
2. 独立样本外（P4：仅冻结后前向数据，holdout 不可用）扣成本净 carry 为正；
3. 去最大单仍正（前向窗口内最大单笔净 carry 剔除后仍正；
   carry 语境下“单”为单次持有周期的净 carry）；
4. 滑点敏感性全正（三档均正）；
5. 样本量与跨期稳定性达到冻结时定的标准（§4 最低样本量＋任一分段不为负，
   或分段为负已在报告首页标明且 verdict 据此从严）；
6. 模拟盘先行门通过（用户另行批准，模拟盘真跑正按本模板算）；
7. 可执行性档位为当前可执行（P4 ETH 对：是；BTC 对：否——
   BTC 对即使统计向好也不得贴此标签，除非本金门槛已满足并重登记）。

**杀线裁决表（与登记 §8 一致，此处为执行版）：**

| 编号 | 杀线 | 评估时点 | 后果 |
|---|---|---|---|
| K1 | 滚动 90 天年化净 carry ≤ 0 | 每月末（探索＋前向） | 淘汰 |
| K2 | 全窗口扣全部成本后净 carry ≤ 0 | 预注册评估点（前向 ≥180 天） | 淘汰 |
| K3 | 现货腿最小名义 > 对子规模（20U） | 设计阶段复核 | 降级为仅研究候选 |
| K4 | 近 365 天均值资金费 ≤ 0 | 每月末 | 淘汰 |
| K5 | 滚动 90 天 p95 \|日基差变动\| > 30 × 日均资金费 | 每月末 | 淘汰 |
| K6 | 中央口径往返成本 ÷ 近 365 天日均资金费 > 90 天 | 设计审查（现货费率核实后） | 淘汰 |
| K7 | carry 日收益与 ETH 日收益 \|ρ\| > 0.5 | 每月末／评估点 | 淘汰或重分类 |
| K8 | 任一腿强平 | 随时 | 立即暂停＋重审；同设计再发 → 淘汰 |

**暂停触发（非杀线，暂停＋审查，不自动恢复）：** 交易所维护、资金费规则变更、
USDT 偏离 > 2% 持续、ADL 强制减仓、数据缺口连续 > 24 小时。
暂停期间不新开仓（纸面亦然）；恢复须重新评估杀线状态，不得静默续跑。

## 7. 方法论承接（上一阶段有效部分，原样保留）

- **脚本门禁＋单人 AI 抽查**：确定性脚本检查（数据缺口、时间戳连续性、
  杀线计算复核）作常驻门禁，单人 AI 审计作抽查层；完整多智能体架构继续暂停。
- **六项登记扩展**：本登记（假设／数据／成本／基准／淘汰／已用数据）
  即 M2 式登记的 P4 实例；证伪线检验前写死、事后不得补写。
- **无参数搜索**：草案数值来自机制与成本原则（见草案数值来源表），
  回测结果不得反向改参数（纯 bug 修复须单列说明）。
- **模拟盘先行门不变**：任何策略先上模拟盘，真跑正才补仓；
  补仓＝新增工资补，不卖定投，两桶不串；“跑正”按 §5 二元标签的严格定义算。
- **失败版本封存**：B1／M1／M3／Faithful Teo 结论不变，不再调参；
  本策略与方向三机制相反，不得以方向三的结论为本策略背书，
  亦不得以本策略的结论为方向三背书。

## 8. 下一步（等用户审查草案后才启动，本方案不做其中任何一项）
