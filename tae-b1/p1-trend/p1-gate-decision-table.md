## D-G1：执行收盘定义与月末对齐

### 1. 推荐方案及理由

**推荐：信号日＝当月最后一个美股交易日收盘；执行日＝下一个美股交易日，
执行时刻＝美东 16:00 常规收盘，执行价＝该时刻 Gate 合约 mark price。**

理由：

- 与草案 F3 结构完全一致（月末收盘算信号、次日收盘执行），只把“收盘”二字
  落到时钟（美东 16:00）与价格字段（mark price），**不改频率、不改滞后、不改信号**。
- 与机制序列同钟：Yahoo adjclose 收盘即美东收盘，双轨价差最小，
  机制轨与文献（MOP 月末形成期惯例）的可比性不受损。
- 美收盘是 TLT/GLD 当天流动性最好的窗口（实测：TLT 有量根集中在美股时段），
  价差最可能收窄；薄腿统一用 mark price 而不用 last，避免陈旧成交价
  （快照中 TLT last 相对 mark 偏离约 0.32% 就是实例）。
- 避开 UTC 0 点静态价：TLT/GLD 夜间与周末价格多为沿用价，用静态价“成交”
  等于假成交，执行价失真无法事后审计。

### 2. 其他可选方案

- **(a) Gate UTC 0 点日收盘执行**：优点是时钟统一、亚洲时段可操作；
  缺点是与机制序列差 4 小时，周末与夜间多为静态价，且月末对齐可能差一天
  （UTC 月末 vs 美股月末），执行价失真风险高于 (a) 的便利收益。
- **(b) 下一美股开盘执行**：优点是避开收盘时段波动；缺点是持有期多出约 17 小时
  隔夜缺口，执行日落入下一月（月末对齐破坏），开盘价差可能更宽；
  且 Gate 永续并无收盘集合竞价，“避开集合竞价噪声”这一理由在此不适用。
- **(c) 执行日全天 VWAP／均价执行**：优点是降低单点滑点；缺点是引入日内路径依赖、
  与草案“收盘执行”口径冲突、需要日内数据与执行算法，属新规则，
  须另行登记——不推荐作默认方案。

### 3. 对策略经济机制和历史可比性的影响

- 推荐方案：机制不变（形成期、持有期、月度再平衡逻辑与 MOP 一致），
  历史可比性完整保留——机制轨窗口 A（2020-11 起）、B（2005-11 起）仍按美股日历切分，
  与草案 F8 一致。
- (a) UTC 收盘：机制逻辑本身不变，但执行月份与信号月份可能错位，
  机制轨收益与文献月度动量收益不再严格同口径（持有期被 UTC 日历切分），
  可比性打折。
- (b) 开盘执行：持有期结构改变（多出隔夜段），月度动量 premium 的定义
  从“收盘到收盘”变为“收盘到开盘”，与文献口径不一致，须在报告中单列口径差异。
- (c) VWAP：机制仍为月度动量，但执行收益不再是收盘价收益，
  与一切收盘价基准（adjclose 买入持有）不可直接比较，须另建 VWAP 基准。

### 4. 对实际 Gate 执行成本的影响

- 推荐方案：费用不变（taker 同档）；价差成本以美收盘复测为准，
  预期薄腿价差窄于盘前快照（假设，未核实，见第 5 点），
  因此快照算出的 TLT 0.33%／GLD 1.10% 换腿成本可能是**高估**，
  不得直接当作美收盘成本。
- (a) UTC 收盘：表面费用相同，隐藏成本是静态价执行缺口
  （沿用价与下一真实成交价之差），事前无法量化、事后难以归因，
  属于最差的成本透明度。
- (b) 开盘执行：承担完整隔夜缺口收益／亏损（方向不定），
  且开盘价差可能宽于收盘价差，期望成本不低于推荐方案。
- (c) VWAP：期望滑点可能低于单点收盘执行，但需要日内执行能力与数据成本，
  且未成交风险（VWAP 偏离）须另行建模。

### 5. 尚未核实的事实与验证方法

- **TLT/GLD 在美收盘时刻的价差与深度**：盘前快照不能替代。
  方法：在美东 16:00 前后记录订单簿快照（仅观察、不下单），连续 5–10 个交易日，
  计算半价差与 0.1%／0.5% 内深度；订单簿无法事后回补，此项须前向观察。
- **Gate mark price 在 16:00 ET 时戳的可得性**：方法：核查 Gate API 是否提供
  mark price 历史端点；若无，以 1m last-price K 线在收盘时刻的值作代理，
  并在报告中声明代理缺口（薄腿 mark 与 last 的偏离，见快照 TLT 约 0.32%）。
- **月末对齐边缘情形**：月末落在周末／节假日时，“最后一个美股交易日”的
  枚举。方法：对照 NYSE 日历枚举 2026–2027 年各月末，写入冻结版附录（纯日历工作，无需数据）。

## D-G2：F1 入选标准 #2 的历史口径（标的历史 vs 合约历史）

### 1. 推荐方案及理由

**推荐：拆分口径——机制历史＝标的历史，执行历史＝合约历史，两者分别列示、分别设门。**

- 机制历史：ETF 现货历史（SPY 1993 起、QQQ 1999 起、TLT 2002 起、GLD 2004 起）
  与加密永续历史（BTC/ETH 2019 起）满足原 #2“≥5 年”的意图
  （意图是保证机制验证有足够样本、避免短历史过拟合）。
- 执行历史：Gate 合约历史如实列示（SPY/QQQ 约 57 天、GLD 约 135 天、TLT 约 273 天、
  BTC/ETH 自 2019 年），**不设 5 年门槛**，改为“执行验证仅覆盖合约存续期，
  不足部分以后向积累补足”（前向执行观测次数作为门指标，阈值冻结前定，不事后补数）。
- 理由：#2 的原意图是机制样本充足，不是合约存续久；把两者混为一谈，
  要么因技术性原因错杀机制（合约短≠机制假），要么用现货历史给合约执行背书
  （数据冒充）。拆分是唯一同时保住两个意图的读法。

### 2. 其他可选方案

- **(a) 严格按合约历史判 #2**：SPY/QQQ/GLD/TLT 全部不通过，
  Gate 路线下 P1 直接淘汰。后果：等于用通道技术性否决机制，
  且与用户“渠道改为 Gate”的决定直接冲突——除非用户接受该后果并改回 IBKR 通道，
  否则不推荐。
- **(b) 只按标的历史判，不披露合约历史短**：机制可比性保留，
  但执行就绪度被掩盖（成本与流动性 regime 只观测了 30–273 天，
  压力 regime 根本没见过），属于报喜不报忧——不推荐。
- **(c) 混合门（推荐方案的变体）**：机制轨按标的历史判，执行轨设前向观测门
  （例如累计观测到的 Gate 调仓次数达到约定值后才可判执行轨通过，
  次数阈值冻结前定）。与推荐方案实质相同，只是把“前向补足”写成了正式门——
  若用户希望执行门更硬，可选此变体。

### 3. 对策略经济机制和历史可比性的影响

- 推荐方案：机制可比性完整（与 MOP 文献、与 P1 自身 A/B 窗口、与 M1/M3 轮的
  报告口径均一致，因为机制序列仍是现货历史）；执行可比性单独报告，
  不与文献比较（文献没有 Gate 合约执行序列可比）。
- (a) 严格合约口径：机制可比性被通道选择破坏——同一机制换个通道就“历史不足”，
  说明该口径测的不是机制，而是通道年龄，逻辑上站不住。
- (b) 标的历史唯一口径：机制可比性表面完整，但执行历史短的事实被隐藏，
  后续若有人把机制轨收益直接读成“Gate 可执行收益”，可比性在传播中失真。
- (c) 混合门：与推荐方案相同，仅执行 verdict 的时间更晚（更保守），
  机制可比性不受影响。

### 4. 对实际 Gate 执行成本的影响

- 推荐方案本身不改变任何费率／价差／资金费数字；但它决定了成本估计的
  不确定性带宽：执行历史短 → 成本 regime（压力价差、资金费尖峰、分红调整）
  的观测样本小，成本模型必须携带更宽的敏感性带，直至前向积累。
- (a) 严格口径：执行成本问题直接消失（路线被否），但代价是放弃整个 Gate 通道。
- (b) 标的历史唯一口径：成本不确定性被低估（用现货历史的长样本
  掩盖合约成本的短样本），可能导致部署时成本超预期。
- (c) 混合门：与推荐方案相同，仅执行 verdict 更晚，成本带宽随前向积累逐步收窄。

### 5. 尚未核实的事实与验证方法

- **是否存在合法的更长股票永续历史**：方法：核查 Gate 历史数据下载中心
  与 API 分页行为（candlesticks 单次上限 1000 根的分页方式）；
  注意：合约上线前根本没有交易，任何声称的上线前“合约价”都是现货合成价，
  必须标注为合成、不得当作合约历史。
- **前向执行观测门的度量**：方法：冻结版中定义观测单位（一次 Gate 调仓执行
  ＝一次观测）与阈值（冻结前定），并规定观测期间只记录、不裁决，
  避免用观测中的表现反向改阈值。

## D-G3：滑点档改为分资产（替代统一 0.05% 中央档）

### 1. 推荐方案及理由

**推荐：分资产中央档＋敏感性档；档位结构冻结前定，数值以美收盘复测为准，
在复测完成前一律保持 TBD，不得用盘前快照数值直接填档。**

- 结构：沿用草案 §3.2 的成本表达式形式（费用项与滑点项分离），
  滑点档按资产分设：流动腿（SPY/QQQ/BTC/ETH）与薄腿（TLT/GLD）分档；
  敏感性档沿用草案逻辑（0 档／中央档／2×中央档），使档位体系与草案可衔接。
- 理由：快照证据已证明统一档同时犯两个方向的错误——
  对流动腿偏保守（实测换腿成本约 0.10% vs 草案中央档隐含 0.20%），
  对薄腿严重低估（TLT 约 0.33%、GLD 约 1.10% vs 0.20%）。
  统一档在薄腿上的低估不是舍入误差，是 1.7 倍与 5.5 倍的系统性偏差，
  继续用统一档等于在成本模型里内置乐观假设（正是 B1 审计点名的错误类）。

### 2. 其他可选方案

- **(a) 维持统一 0.05% 中央档**：优点是与 M1/M3 轮口径完全一致、报告可比性最强；
  缺点是 GLD 腿每次换腿成本被低估约 0.90%（腿名义口径），
  若 GLD 换腿频繁，总成本低估可观，且低估方向单一（永远偏乐观），不可接受。
- **(b) 统一提高到最差腿水平（如 0.50% 滑点档）**：优点是覆盖薄腿；
  缺点是对流动腿高估约 5 倍，策略 verdict 被成本假设单方面压低，
  且与各轮统一口径断裂——保守不等于正确。
- **(c) 改限价／maker 执行降滑点**：优点是理论上 maker 可省价差甚至拿返佣；
  缺点是执行假设从 taker 改为 maker（草案 F3 为市价 taker），属规则变更，
  且薄腿 maker 成交不确定（挂单可能在收盘时刻不成交），须另行登记并验证成交率——
  不推荐作默认方案，可作未来变体登记。

### 3. 对策略经济机制和历史可比性的影响

- 推荐方案：信号机制零影响（形成期、调仓、权重、出口全不动）；
  历史可比性通过“双档并报”保留：报告同时列统一档（与 M1/M3 轮可比的敏感性线）
  与分资产档（ verdict 档），读者可桥接两套口径，不会因改档而无法对照旧报告。
- (a) 统一档：机制可比性最强，但成本可比性是假的（薄腿成本被系统性压低，
  与真实 Gate 执行不可比）。
- (b) 最差腿统一档：机制不变，但成本口径与各轮断裂，且 verdict 被人为压低，
  与文献（多忽略价差）的比较也会失真。
- (c) maker 执行：执行假设改变，若与 taker 基准比较，机制相同但执行收益不同，
  须单列执行变体，不得与 taker 版合并报告。

### 4. 对实际 Gate 执行成本的影响

- 推荐方案：成本估计更接近真实——流动腿成本下调（快照换腿约 0.10% vs 草案 0.20%），
  薄腿成本上调（TLT 约 0.33%、GLD 约 1.10%，快照值，美收盘复测后修正）。
  组合净影响取决于各腿换腿频率（信号翻转次数），**在回测前不得估算净影响**；
  公式为：年化成本拖累 ≈ Σ_腿（年换腿次数_腿 × 换腿成本_腿 × 权重_腿），
  其中换腿次数在冻结前是未知数，任何净数字现在都是编造。
- (a) 统一档：组合成本被低估，低估量集中在 GLD/TLT 换腿月。
- (b) 最差腿档：组合成本被高估，高估量集中在流动腿换腿月。
- (c) maker：若成交，成本可低于 taker 档；若不成交，错过调仓的成本
  （权重偏离＋下月追单）可能远大于省下的价差，净效应不定。

### 5. 尚未核实的事实与验证方法

- **美收盘时刻各腿价差与深度**：方法同 D-G1 第 5 点（16:00 ET 订单簿快照，
  5–10 个交易日，仅观察）。
- **价差的 regime 稳定性**：快照为单点，价差是否在压力日（如 FOMC／GDP 日）
  系统性走宽未知。方法：多时段快照对照（平静日 vs 宏观日），
  描述性统计，不得用单日快照定档。
- **GLD 价差是否随时间收窄**：合约上线仅 135 天，流动性可能仍在成长。
  方法：每月一次快照日志（观察性），档位在冻结后仍可按约定程序复核
  （复核程序冻结前写死，不得事后随意改档）。

## D-G4：基准双轨与杀线适用轨及执行门

### 1. 推荐方案及理由

**推荐：双轨制——机制轨（Track M）沿用草案全部基准与 K1–K5，
执行轨（Track E）另设五门（E1–E5），两轨裁决分开报告、互不替代。**

- 机制轨：信号用现货价（Yahoo adjclose／币安收盘），成本叠加 Gate 成本模型
  （费用双档、资金费实际序列、分资产滑点档、分红 TBD 项），
  基准沿用草案 F7（各资产买入持有、等权买入持有、SPY 买入持有、波动率缩放基准），
  窗口沿用 F8（A 2020-11 起、B 2005-11 起），K1–K5 全部适用。
- 执行轨：只验证 Gate 执行本身——E1 价差门（执行窗口复测价差有稳定估计）、
  E2 资金费门（滚动 30 天资金费未突破上限的约定比例，比例冻结前定）、
  E3 量化门（各腿实际权重与目标权重偏差 ≤10%，建议值、待裁决）、
  E4 跟踪门（同时间戳跟踪误差标准差 ≤ 阈值，阈值冻结前定）、
  E5 分红门（分红调整规则已书面确认，否则不通过，二值门）。
  执行门不通过 ≠ 机制证伪；机制杀线触发 ≠ 执行问题。
- 理由：单轨制必然犯类别错误——现货历史无法证明 Gate 执行，
  合约历史无法承载 12 个月信号与 K1–K5（SPY/QQQ 连一个形成期都不够，
  K5 样本门直接挡通过）。双轨是唯一让两个问题各自得到裁决的结构，
  且与用户“严格分轨”的要求完全一致。

### 2. 其他可选方案

- **(a) 单轨现货轨（无执行门）**：优点是简单、与草案原设计完全一致；
  缺点是执行风险（价差 regime 变化、分红错误、跟踪断裂）在 verdict 中无位置，
  部署／模拟盘时可能 silently 吃掉收益。
- **(b) 单轨合约轨**：优点是“所测即所交易”；缺点是不可行——
  12 个月信号在合约价上算不出，K1–K5 无序列可判，K5 直接挡通过至 2031 年后，
  等于用样本门杀死一个机制问题。
- **(c) 现货＋合约拼接序列**：优点是表面上样本最长；缺点是致命的——
  拼接序列从未真实交易过，既不是现货收益也不是合约收益，
  用它判杀线等于用合成数据冒充验证，**明确禁止**。

### 3. 对策略经济机制和历史可比性的影响

- 推荐方案：机制可比性完整保留（Track M 与 MOP 文献、与 P1 自身 A/B 设计、
  与 M1/M3 轮六问报告同口径）；执行轨是新增维度，不与文献比较，
  其可比性体现在“实现缺口”（modeled vs realized）这一行上，
  而不是混进机制收益里。
- (a) 现货单轨：机制可比性完整，但执行可比性缺失——
  读者无法区分“机制有效”与“Gate 上可执行”。
- (b) 合约单轨：机制可比性丧失（无机制序列可比），历史可比性无从谈起。
- (c) 拼接：两种可比性同时丧失，且失真方向不可审计。

### 4. 对实际 Gate 执行成本的影响

- 推荐方案：成本归因清晰——Track M 成本＝模型化 Gate 成本
  （费用／资金费／分资产滑点／分红 TBD）；Track E 成本＝实现成本
  （模拟盘／前向纸面的实际成交价、实际资金费结算、实际分红调整入账）；
  两者之差＝实现缺口，单列报告，不藏进策略收益。
- (a) 现货单轨：实现缺口被藏进策略收益，成本低估或高估无法定位。
- (b) 合约单轨：成本序列太短，成本 regime（压力价差、资金费尖峰）未观测，
  成本估计方差极大。
- (c) 拼接：现货段成本与合约段成本口径不同，拼接后的“总成本”无意义。

### 5. 尚未核实的事实与验证方法

- **跟踪误差量级**：方法见差异报告 §3.3——Gate 合约在美东收盘时刻的价格
  与 Yahoo 当日收盘价配对，计算日收益差序列（均值、标准差、最大偏离、
  分红除息日跳变）；禁止用 Gate UTC 日收盘直接对 Yahoo 美收盘（4 小时时差
  会制造假跟踪误差）。
- **实现成本与模型成本之差**：方法：冻结＋用户批准后，前向纸面／模拟盘
  记录实际成交价、实际资金费结算、实际分红入账，与模型化成本逐项对账；
  在此之前（当前）不得用任何模拟成交宣称实现成本。
- **资金费长期历史**：公开端点仅 30 天。方法：核查 Gate 历史数据下载渠道
  或其他资金费历史来源；若无，早期资金费假设在报告中标“未核实”，
  不得用近 30 天均值外推全年。

## D-G5：保证金模式、取整规则、合约下线条款（资金规模单独评价，杠杆不掩盖量化）

### 1. 推荐方案及理由

**推荐：逐仓 1x＋向下取整＋先平后开＋合约下线条款改写；资金规模评价用规模函数，
不以 56U 为约束（按用户指示改按模拟盘金额，金额待确认后代入）。**

- **逐仓 1x**：每腿独立保证金＝名义，与草案 F4“永续腿保证金＝名义（1x）”
  最接近；一腿的亏损／资金费侵蚀不传染其他腿；1x 在全部六合约杠杆范围内
  （最小杠杆均为 1x）。
- **向下取整（floor）**：张数向下取整，保证总名义 ≤ 组合价值（草案 F4 上限）
  在任何规模下都不被取整行为本身打破；剩余现金以 0% 持有（草案 F4），
  取整拖累如实披露为实现缺口。
- **先平后开**：换腿时先平旧腿、再开新腿，避免短暂双倍保证金占用导致
  小资金下换腿失败；顺序写进冻结版执行细则。
- **合约下线条款改写**：草案 F1 的 ETF 退市条款改写为合约下线条款——
  以 Gate 公告＋合约 `in_delisting` 字段为准，下线公告后首个可交易日退出，
  按最后可交易价计；此后该腿退出组合，基准同步处理（与草案退市逻辑同构，
  只是对象从 ETF 换成合约）。
- **规模函数（不以 56U 为约束）**：单腿目标＝组合价值 P／6；
  最近取整的最大偏差上界 ≈ 0.5 × 单张名义 ÷ 单腿目标，
  向下取整的单腿最大未投资额＝单张名义（总额未投资上界＝六腿单张名义之和）。
  参照格（最近取整，ETH 小数情形；ETH 整数情形单列）：

| 组合价值 P | 单腿目标 | 各腿最近取整最大偏差 | 总额未投资上界（向下取整） |
|---|---|---|---|
| $200（小规模锚点） | $33.33 | 约 8.0%（ETH 小数情形，QQQ ＋8.0% 为最大；ETH 整数情形为 −30.3%／＋39.5%） | ＜$58.06（ETH 整数）／＜$34.82（ETH 小数） |
| $1,000（登记 §3.4 格） | $166.67 | 约 1.9%（ETH 小数情形；ETH 整数 7 张 −2.4% 为该规模最大偏差） | 约 5.81%（ETH 整数）／约 3.48%（ETH 小数） |
| $10,000（登记 §3.4 格） | $1,666.67 | 约 0.21%（ETH 小数情形；ETH 整数 72 张 ＋0.41% 为该规模最大偏差） | 约 0.58%／约 0.35% |
| $100,000（登记 §3.4 格） | $16,666.67 | ＜0.05% | ＜0.06% |

  读法：量化偏差随规模增大而缩小，在 $1k 量级已收敛到约 2.4% 以内，
  在 $10k 量级约 0.4% 以内；**模拟盘金额一经用户确认，即可代入上式算出精确偏差表**，
  本表不预设该金额。

### 2. 其他可选方案

- **(a) 全仓 1x（统一账户共享保证金）**：优点是现金管理简单、无需逐腿划转；
  缺点是一腿的 adverse move／资金费流出侵蚀共享缓冲，
  分红错误类事件（BEN 型）的冲击会扩散到全组合；且与草案“保证金＝名义”
  的逐腿直觉不一致——不推荐作默认，可作部署时备选（须用户另批）。
- **(b) 最近取整／向上取整**：优点是平均权重更接近目标；
  缺点是可能突破总名义上限（56U 下最近整数总额 $61.76＞$56 即实例），
  须附加“超限时按比例缩减最大腿”等补丁规则，增加复杂度与审计面——
  不推荐作默认；若用户偏好最近取整，须同时冻结超限处理规则。
- **(c) 提高杠杆“解决”小资金（明确拒绝）**：杠杆只改变保证金，
  不改变名义与张数——2x 下每腿仍需同样张数，量化偏差分毫不差；
  同时强平距离大约减半（1x 约 97–99% → 2x 约 49–50% 量级），
  风险上升而问题未解决。**本方案违反用户“不得通过提高杠杆掩盖”的禁令，
  列出仅为说明拒绝理由，不得采纳。**

### 3. 对策略经济机制和历史可比性的影响

- 推荐方案：信号机制零影响；实现权重与目标权重的偏差作为**实现缺口**
  单独报告，不折进机制收益——文献（假设连续权重）与 P1 机制轨的可比性
  因此保留，缺口大小随规模缩小而透明化。
- (a) 全仓：机制不变，但一腿的风险事件会通过共享保证金传导，
  组合层面的回撤路径与逐仓不同，机制轨（逐腿独立假设）与实现轨的
  回撤可比性打折。
- (b) 最近／向上取整：机制不变，但权重偏差方向不定（时而超配、时而低配），
  实现缺口的符号不稳定，报告须逐月列示实际权重，否则与目标权重的比较失真。
- (c) 提高杠杆：机制收益（名义口径）不变，但风险口径改变
  （强平距离、保证金占用），与草案 1x 前提下的风险描述不可比——
  且 P1 的风险匹配基准（草案 F7）是在 1x 名义下定义的，改杠杆等于改基准口径。

### 4. 对实际 Gate 执行成本的影响

- 推荐方案：逐仓 vs 全仓不改变费用／资金费（同名义、同方向下结算相同）；
  向下取整的成本是**现金拖累**：未投资部分收益为 0%，拖累 ≈ 未投资比例 ×
  （策略收益 − 0%），在 $1k 量级约 ≤3.5–5.8% 的仓位未投资（非收益拖累数字，
  收益拖累＝未投资比例 × 策略收益率，策略收益率未知故不估算）；
  先平后开避免换腿失败带来的追单成本（失败后下月再调的权重偏离＋额外价差，
  未量化，靠顺序规则预防）。
- (a) 全仓：费用相同，风险成本上升（共享缓冲侵蚀），无直接费用收益。
- (b) 最近／向上取整：现金拖累更小（平均），但超限风险带来强制缩减成本
  （缩减腿的选择本身就是一次非规则交易）。
- (c) 提高杠杆：费用／资金费不变（按名义计），但强平尾部风险上升，
  且可能触发追加保证金导致非计划平仓——成本为风险成本，不是费用节省。

### 5. 尚未核实的事实与验证方法

- **ETH 小数下单的最小步长**：方法：用户在 Gate 订单票面读取最小张数／步长字段；
  或核查 Gate API 文档对 `order_size_min＝0 ＋ enable_decimal＝true` 的语义说明。
  在确认前，ETH 腿的量化表须同时列整数情形与小数情形（本表已如此处理）。
- **股票永续是否支持逐仓模式**：方法：核查 Gate 期货保证金模式文档
  与订单票面的保证金模式字段（逐仓／全仓切换是否存在于股票永续）。
- **合约下线通知期与程序**：方法：核查 Gate 合约细则与历史下线公告
  （通知提前量、下线日交易安排、最后结算价规则）。
- **模拟盘金额**：已确认（见下节精确表）。方法：用户确认具体金额后，代入 §1 的规模函数
  （单腿目标＝P／6、偏差上界＝0.5×单张名义÷单腿目标）算出精确表；
  在此之前，本表不以任何单一金额作 verdict。

## D-G6：费用最终口径、分红调整确认、ETH 小数、地区资格与 API 权限

### 1. 推荐方案及理由

**推荐：确认制——每个事实以其唯一可信来源为准，确认前一律保持 TBD，
确认后单档＋另一档作敏感性；三项确认均为执行轨的前置门（D-G4 的 E5 与权限门），
未确认＝门未通过（不是假设通过，也不是判定失败，是“待确认”状态）。**

- **费用**：以用户订单确认页的 all-in 费率为准（含 VIP 等级、GT 抵扣、返佣状态）；
  确认前报告双档并列（官方口径 taker 0.05%／API 字段口径 taker 0.075%），
  确认后以票面档为中央档、另一档为敏感性档。
- **分红**：以 Gate 永续合约细则书面内容（或官方客服书面回复）为准，
  包括各标的（SPY/QQQ/TLT/GLD）的调整额计算、时点、扣缴、除息日清单；
  确认前分红项保持 TBD（不得填 0，不得用 CFD 规则、不得用 10% 扣缴传闻）。
- **权限**：地区资格（App 内能否看到并交易股票永续）与 API 期货权限
  （API 管理页的权限与 IP 白名单状态）由用户本人在 App 内确认，
  **不索取、不记录密钥**；确认前权限门为“待确认”。
- 理由：这三项是公开数据无法裁决的事实（账户专属或产品细则专属），
  用第三方表、相邻产品规则或传闻数字填充，正是 B1 审计点名的
  “合理但偏乐观的假设”错误类；用户亦已明令“未经核实不得填默认值”。
  确认制把“不知道”保持为“不知道”，是唯一不污染后续 verdict 的做法。

### 2. 其他可选方案

- **(a) 官方口径作中央档（0.05%）、API 字段作敏感性**：作为**报告惯例**可接受
  （官方来源强于 API 字段），但作为**确认**不可接受——
  官方表与 API 字段的差异仍未解释，若用户实际费率确为 0.075%，
  中央档成本将被低估 50%（费用项口径内）。本表将其列为“确认前的报告惯例”，
  不是确认结论。
- **(b) 保守口径作中央档（0.075%）**：方向安全，但若实际为 0.05%（或 GT 抵扣后更低），
  成本被高估，且与各轮 0.05% VIP0 口径断裂——可作敏感性档，不作中央档。
- **(c) 以第三方费率表为准**：**拒绝**——第三方表之间互相冲突，
  且与 API 字段、官方表均不一致；第三方表只能作线索，不能作裁决依据。

### 3. 对策略经济机制和历史可比性的影响

- 推荐方案：机制零影响；但费用档选择会移动机制轨净收益与 K1 敏感性——
  因此在确认前，K1 相关报告须同时列双档结果（若双档下结论一致，
  则 verdict 对费用假设稳健；若不一致，须标注“费用敏感”，不得单档报喜）。
- 分红 TBD 对可比性的影响最大：机制轨基准（adjclose，总收益、分红再投资）
  与执行轨实现（合约＋实际调整入账）之间的缺口＝分红跟踪缺口，
  在确认前无法闭合——报告须把该缺口单列为“未闭合项”，
  不得用 adjclose 收益直接代表合约收益。
- 权限确认对机制无影响，但对执行 verdict 是二值门：
  权限不通过则 Gate 路线不可执行（成本无限大），与机制 verdict 无关，
  两轨裁决必须分开写。

### 4. 对实际 Gate 执行成本的影响

- **费用档差额（可算，不大）**：每换腿费用差＝2×(0.075%−0.05%)＝0.05%（腿名义口径），
  月度频率下年化影响 ≈ 0.05% × 年换腿次数（腿口径，混频未知故不估算净值）——
  相对 GLD 价差（换腿约 1.10%）与加密资金费（多头约 3.7–3.9%/年）是二阶项，
  但纪律上是一阶项（不能把不确定的数写成确定的数）。
- **分红影响（未确认，不得估算净值）**：若调整完整及时，
  多头收、空头扣与价格除息跌幅对称抵消，净影响趋近 0（混合腿净额取决于多空组合）；
  若存在扣缴／延迟／错误调整，则产生拖累或尾部事件（BEN 型），
  其量级在确认前无法写入中央成本，只能列为 TBD＋尾部风险。
- **权限影响**：无直接费用；权限不通过则路线不可行，成本问题让位于可行性问题。

### 5. 尚未核实的事实与验证方法

- **费用（票面裁决）**：方法：用户在 Gate 期货下单确认页读取
  （不下单也可查看费率行）——VIP 等级、taker／maker 费、GT 抵扣开关、返佣状态；
  或登录后 Gate 费率页的个性化费率表。**不得向本表提供密钥或截图中的敏感信息，
  只需用户口头／文字确认档位数字。**
- **分红（书面确认）**：方法：(i) 检索 Gate 公告中各标的的分红调整通知
  （SPY/QQQ 季度、TLT 月度、GLD 无分红预期——逐标的核对）；
  (ii) 核查 Gate 永续合约细则中“分红”章节是否存在及措辞；
  (iii) 官方客服书面回复（留存措辞，不采信口头转述）。
  在任一书面来源确认前，分红项保持 TBD。
- **权限（App 内确认）**：方法：用户在 Gate App 内确认股票永续入口可见性
  （地区资格）与 API 管理页的期货权限状态（不分享密钥）；
  若入口不可见或权限未开通，Gate 路线在权限门上为“待办”，须用户另行决定
  （是否开通／是否换通道），本表不代为决定。
- **资金费长期历史（附带）**：公开端点仅 30 天。方法：核查 Gate 历史数据
  下载渠道或其他资金费历史来源；若无，早期资金费假设标“未核实”，
  不得用近 30 天均值外推全年。
