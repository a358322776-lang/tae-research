# 红队审计可衡量验收方案（补充方案，非执行令）

定位：本方案只是“验收红队审计过程本身”的标尺，不批准红队实验本身。第三阶段隔离沙盒红队实验仍须用户另行批准后才跑。验收通过 ≠ 策略可交易；交易决策仍以冻结后前向检验为准。

两目标分开：本方案服务的是“MUSE 如何更严谨地研究策略”，不是“TAE 如何直接赚到钱”；红队发现的问题进入 M2 登记表走假设-证伪流程，不得直接改 TAE 规则。

## 沙盒规则（红队实验获批后才适用）

1. 只读生产输出、在副本上操作：审计对象一律是 B1 引擎、扫描器、前向观察系统的副本，以及研究报告中的可核查论断；不得改动生产代码、生产台账与冻结规则。
2. 只产意见，不进信号链：红队输出为发现登记与审计意见，不得直接生成交易信号、不得修改扫描器逻辑、不得部署、不交易。
3. 植入缺陷仅存在于沙盒副本：实验结束后副本废弃，植入缺陷不得流入任何生产路径。

## 审计对象与缺陷类别覆盖矩阵（10 类，每类至少 1 个植入缺陷，关键类 ≥2 个）

| 类别 | 含义举例 |
|---|---|
| 未来函数 | 信号用到决策时刻之后才可知的数据（当日收盘后信息、次日新闻、未确认摆动） |
| 手续费/滑点遗漏 | 成本模型缺项或档位错配 |
| 资金费遗漏 | 永续结算未计资金费且未声明“资金费前口径” |
| 幸存者偏差 | 只保留存活币种/时段/成功样本进入统计 |
| 样本选择偏差 | 以后续价格表现挑选定义、样本或参数 |
| 多重检验未校正 | 多实验/多假设共用 α 而无 family-wise 处理 |
| 同根排序 | 同根内入场与止损先后不可判定却默认有利顺序 |
| 带陈旧/过期 | 超 STALE_BARS 的带、过期序列仍被使用 |
| 数据缺口处理 | 缺口被静默补齐或缺口期数据计入统计 |
| 成本模型与执行价假设 | 执行价假设（收盘成交、固定滑点）与实际撮合脱节 |

## 可衡量指标（定义先行，阈值待批）

| 指标 | 定义 |
|---|---|
| 关键缺陷召回率 | 检出的关键植入缺陷数 / 植入的关键缺陷总数 |
| 一般缺陷召回率 | 检出的一般植入缺陷数 / 植入的一般缺陷总数 |
| 精确率 | 真实发现数 / 红队全部发现数（误报计入分母） |
| 干净副本误报 | 在未植入缺陷的干净副本上，红队报出的关键误报数 |
| 覆盖率 | 已审计类别数 / 10 |
| 可复现性 | 重跑同一审计，关键发现一致的比例 |
| 证据完备率 | 附文件＋行号或数据切片的发现数 / 全部发现数 |

## 建议验收阈值（建议值，待用户拍板，非冻结）

- 关键缺陷召回率 ≥80%；一般缺陷召回率 ≥60%。
- 精确率 ≥70%。
- 干净副本关键误报 ＝0。
- 覆盖率 100%（10 类全审计）。
- 关键发现重跑一致率 100%；证据完备率 100%。

未达阈值时结论只能是“审计过程未通过验收”，不得反向解释为“被审计对象有问题”或“被审计对象没问题”——过程验收与对象结论是两回事。

## 一次红队运行的交付物

1. 发现登记表：ID / 类别 / 严重度（关键/一般/轻微，定义见下）/ 证据（文件＋行号或数据切片）/ 建议 / 状态。
2. 覆盖矩阵：10 类各审计与否、植入数、检出数。
3. 记分卡：上表 7 项指标实测值 vs 建议阈值。
4. 未达阈值项的复跑计划（改审计方法，不改被审计对象）。

严重度定义：关键＝可改变结论方向或盈亏符号的缺陷（如未来函数、成本量级错误）；一般＝可改变数值但不改变结论方向的缺陷；轻微＝表述、口径、文档类问题。

## 与 M2 的衔接

红队发现若转化为可检验假设，须进 M2 登记表：检验前写死证伪线，检验数据必须来自冻结后前向流；红队发现本身不是检验结果。
