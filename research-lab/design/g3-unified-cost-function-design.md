# G3 统一成本函数：技术方案（设计稿，未批准实施）

- 性质：设计稿。只读审计 + 方案设计（用户 2026-11-04 12:54 第四条
  授权）；**不改任何引擎代码、不重跑回测、不重写历史数字**。
  实施须逐项另批（见 §6 审批条目）。
- 目标：B1 与 C5（及未来引擎）的成本数字放在同一口径下比较，
  且每个数字能追溯到一条密封的成本规格。

## 1. 现状（只读审计，文件:行）

| | B1（`tae-b1/b1_engine.py`） | C5（`screening-2/c5-exploratory-backtest.py`） |
|---|---|---|
| 计价单位 | R（相对止损距离） | 百分比（相对入场价） |
| 手续费 | `FEE = 0.0005` 单边；`fee_r = 2*FEE/sd`（:38, :295） | `FEE_RT = 0.001` 双边合计（:34） |
| 滑点/价差 | `STOP_SLIP = 0.0005`，仅止损出场、方向调整（:39, :259-262）；EMA/收盘出场按收盘价、无滑点 | 档 `exec = slip + spread`（low 0.00035 / central 0.0008 / high 0.0020，:44-51），入场与出场成交价均含 exec |
| 止损定义 | ATR 距离（`sd`，逐笔不同） | 固定 `STOP_PCT = 0.02`（相对入场成交价，:35） |
| 资金费 | 结算记录精确和，计入 R（`trade_numbers`） | 收盘出场精确和；止损日为前缀极值区间 `(lo, hi)` |
| 引擎状态 | 已封存，冻结代码零触摸 | 已退出候选池，冻结代码零触摸（main） |

口径差异共 5 处：单位、手续费基准、滑点范围、价差有无、资金费
表示法。直接比较两引擎历史数字会把口径差当成策略差。

## 2. 设计：比较层统一，引擎层不动

新增 `research-lab/cost_model.py`（仅标准库），三件套：

1. **CostSpec（规格）**：`fee_per_side`、`slip_entry`、`slip_exit`、
   `spread`、`funding_mode`（exact/interval）。规格值 = 上表审计
   常量，不得发明新费率；存入密封文件 `cost-specs-v1.json` +
   SHA256 记录（与验证标准同机制），改动须批。
2. **纯函数 `apply_costs`**：输入（入场价、出场价、方向、
   资金费记录、窗口、规格）→ 输出分解
   `{gross_pct, fee_pct, slip_pct, funding_pct, net_pct}` 及 R 换算
   `to_r(net_pct, stop_distance_pct)`。确定性、无 I/O、无引擎依赖。
3. **适配器（仅比较用）**：`b1_to_common(trade)`、
   `c5_to_common(leg, tier)`——把引擎已有输出翻译成统一分解，
   **不调用引擎代码、不改引擎输出**。历史数字不重算，只标注
   “原生口径、统一前、跨引擎不可比”。

验证器扩展：`check_fee_r` / `check_stop_exit` / `check_funding_interval`
接受 CostSpec 参数；旧调用保持默认行为（向后兼容）。

## 3. 测试方法

- 已知答案（golden，合成数据，零正式回测）：B1 已知交易在
  B1-spec 下复现净 −1.0845R；C5 central 腿在 C5-central-spec 下
  复现净区间 (−0.022284, −0.022084)（取自腿函数级对照，不经
  `run_tier` 真实数据）。
- 性质测试：零成本规格下 net == gross；费率单调（费率越高净值
  越低）；资金费窗口 `(t0, t1]` 精确性；区间包含全部前缀极值。
- 回归门：适配器输出须与引擎原生分解在各自规格下逐项一致
  （容差 1e-12）；不一致即测试失败。

## 4. 影响范围

- 改：新增 1 个模块 + 1 个密封规格文件 + 测试；验证器新增可选
  参数；登记记录新增可选字段 `cost_spec_version`（加法式、向后
  兼容，见 A3）。

  登记库现有行。

  不返工，只在引用时加注口径声明。
