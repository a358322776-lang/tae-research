# 最终测试集隔离：技术方案（设计稿，未批准实施）

- 性质：设计稿。只读审计 + 方案设计（用户 2026-11-04 12:54 第四条
  授权）；**不创建任何测试数据、不写任何数据文件**。实施须逐项
  另批（见 §6 审批条目）。
- 目标：最终测试集一旦冻结，任何研究主体在晋级前都读不到、改不了
  它；一切接触都可审计。现状缺口见 §1。

## 1. 现状缺口（只读审计）

1. **测试集不存在**（Phase 0 缺陷 D12）：没有任何最终测试数据，
   只有训练/探索用的快照。隔离机制无物可隔——本方案先建机制，
   数据冻结是独立的后续批准（B3）。
2. **无独立目录**：快照与登记库同处 `research-lab/state/`，
   目录权限 `drwxrws---`、文件多为 `rw-rw----`（可写、可重命名/
   删除）；资金费快照文件虽为 `0o444`，所在目录仍可写。
3. **无密封实例**：验证器 `seal_directory` / `verify_sealed_directory`
   函数已备（18 项测试全过），但没有任何目录被密封、没有任何
   清单文件存在。
4. **无访问日志**：无人记录谁在何时读过哪些数据；研究 Agent
   若读到测试数据，事后无法发现。
5. **方案约束未落地**：实施方案 v1.1 §5/§6 要求“验证器独占最终
   测试集；Research Agent 与 Codex 不可读；只知存在与样本量区间；
   访问日志；冻结后新数据自动划入测试集”——以上均未实现。

## 2. 设计：目录 + 清单 + 只读访问器

```
research-lab/test-sets/final-v1/
  spec.md            # 冻结规格：标的池、窗口、字段、排除规则、冻结时间戳（进仓）
  summary.json       # 仅计数：bar 数区间、标的数量（进仓；Research Agent 可读的唯一信息）
  manifest.json      # 每文件 SHA256 + spec 哈希（进仓；原始数据哈希，不含数据）
  data/              # 快照文件，0o444；目录 0o555（本地-only，永不进仓）
  access-log.jsonl   # 只追加访问记录（本地-only）
```

新增 `research-lab/testset.py`（仅标准库），唯一访问入口：

- `open_final_test(purpose, experiment_id)`：先校验全部文件哈希
  与清单一致 → 校验 `purpose == "final-evaluation"` 且实验已登记
  为终评状态（只读读登记库）→ 返回内存中的只读解析副本（不
  交出文件句柄）→ 追加访问记录（时间、实验 ID、用途、哈希）。
  任一校验失败即拒绝并记日志。
- **无写 API**：访问器不提供任何写/删/改接口；目录与文件权限
  （0o555/0o444）为纵深防御。
- **切分扫描**：验证器新增检查——非终评阶段的实验 SPEC 文本不得
  包含 `final-v1` 路径引用；命中即登记拒绝。

如实说明的局限：同一 UID（本 VM 为 root）下文件权限可被绕过，
真正的强制力来自哈希校验 + 访问日志 + 验证器拒绝 + git 中的
清单留痕；UID/容器级隔离属沙箱加固范畴（C5），须另行复核。
本方案不声称权限本身不可绕过。

## 3. 测试方法

- 篡改拒绝：改动任一数据文件 1 字节 → 访问器拒绝并记日志。
- 只读性：访问器返回对象不可写回文件；尝试经访问器写 → 无此
  接口（API 检查）；权限快照断言目录/文件 mode（root 环境下
  为提示级，见 §2 局限）。
- 日志完整：每次访问（含拒绝）恰好一条记录；日志只追加（复写
  检测：行数只增不减）。
- 切分扫描：含 `final-v1` 引用的非终评 SPEC 被拒绝；终评 SPEC
  在终评状态下放行。
- 密封往返：`seal_directory`/`verify_sealed_directory` 对
  `data/` 的密封与复核（改动/新增/缺失均被发现）。
- 机制测试用合成数据目录（tempfile），**不用真实测试数据**
  （数据尚不存在）。

## 4. 影响范围

- 改：新增目录结构（空 `data/`）+ `testset.py` + 验证器扫描
  检查；`spec.md`/`summary.json`/`manifest.json` 模板进仓。
- 不改：现有快照、登记库、引擎代码、生产 cron；不创建、不
  写入任何真实测试数据（B3 之前 `data/` 保持为空）。
- 冻结后：新数据自动划入测试集的规则写入 `spec.md`（机制），
  实际划入动作须冻结事件批准。

## 5. 回滚方案

删除 `testset.py` + 清单模板；`data/`（空）随目录删除；无实验
依赖测试集（集尚不存在），无数据需要恢复。若 B3 冻结已发生，
回滚 = 作废清单（访问器拒绝一切访问），数据原样保留、永不
静默复用。回滚须记录在案。

## 6. 审批条目（逐项申请，互不连带）

- **B1**：规格模板 + 清单格式 + 摘要格式（§2，不含数据）。
- **B2**：只读访问器 + 访问日志 + 验证器切分扫描（§2–§3，
  以空数据目录测试）。依赖 B1。
- **B3**：`final-v1` 冻结/创建（数据窗口决策 + 一次性写入 +
  密封）。依赖 B1/B2，窗口与标的池须单独批准。
  任一未批均不得实施；B3 未批则 `data/` 永久为空。
